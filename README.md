# MedApp Server

REST API для домашней аптечки: что есть в наличии и что пора принять. Аптечки бывают общими —
семья, соседи. Система приватна по замыслу: о человеке не хранится ничего, кроме идентификатора и
хеша ключа.

## Технологии

- Kotlin 2.4, Java 25
- Spring Boot 4, Spring Security (JWT)
- Exposed — запросами, без ORM
- kotlinx.serialization на проводе
- PostgreSQL 18, Testcontainers в тестах
- Caffeine (через Kotlin-обёртку Adeine)
- Docker & Docker Compose

## Архитектура

Слои разговаривают строго вниз: контроллеры → прикладные сервисы → оркестраторы → сервисы
агрегатов → хранилища. Подробное описание — в [ARCHITECTURE.md](ARCHITECTURE.md), правила и то,
чем каждое закреплено — в
[ARCHITECTURE-RULES.md](src/test/kotlin/org/kert0n/medappserver/ARCHITECTURE-RULES.md).

Это часть [MedApp](https://github.com/Kert0n/MedApp) — курсовой работы, где сервер, Android-клиент
и скраппер справочника подключены подмодулями. Документы курсовой лежат там же.

Проект следует принципу **Privacy by Design**:

- о человеке хранятся только идентификатор и хеш ключа — ни имени, ни почты, ни телефона;
- журнал приёмов в базу не попадает: он слишком персонален для таблицы;
- недоступное неотличимо от несуществующего: иначе по коду ответа перебором узнаётся чужое;
- логи идут только в консоль и не содержат идентификаторов и количеств.

## Модель данных

- **User** — идентификатор и хеш ключа, больше ничего.
- **MedKit** — аптечка: множество участников. Равноправных: ни владельца, ни ролей.
- **Drug** — **упаковка**, а не «лекарство вообще». Пополнения не бывает: докупил пачку — завёл
  вторую упаковку. Пустая выбрасывается.
- **Reservation** — бронь: заявка человека на часть упаковки. Может превышать остаток — сколько
  из неё оставить, решает владелец, а не сервер.
- **DrugTemplate** — справочник Vidal, только для чтения.

Единицы измерения и формы выпуска (`QuantityUnit`, `FormType`) общие для справочника и заведённых
руками упаковок: «шт» — одна единица на систему, а не две одинаково написанные строки.

## Аутентификация и регистрация

1. `POST /v1/auth/register` — регистрация; требует секрет в заголовке `X-Registration-Token`
   (см. `registration.secret`). В проде пустой секрет не даёт приложению стартовать.
2. `POST /v1/auth/token` — выдача JWT по HTTP Basic.

Регистрация и выдача токена ограничены по адресу клиента (в кеше — хеши адресов). JWT по умолчанию
живёт 10 минут.

## Версии и предусловия

Команда предъявляет версию того, что видела: полем тела, а где тела нет — параметром запроса
`version`. `ETag` и `If-Match` не используются: заголовок один, а ответ упаковки несёт два
независимых состояния — саму пачку и картину броней на ней.

| ситуация | ответ |
|---|---|
| версия не прислана | 428 |
| прислан мусор | 400 |
| предъявлена и не совпала | 412 |
| ресурс недоступен или его нет | 404 |
| дубль брони, повторное вступление, версии из тела синхронизации | 409 |

## Эндпоинты

Полный контракт — в [open-api.yaml](open-api.yaml); ниже оглавление.

### Аутентификация

- `POST /v1/auth/register` — регистрация, отдаёт сгенерированные учётные данные
- `POST /v1/auth/token` — JWT по HTTP Basic

### Пользователь

- `GET /v1/users/me` — снимок всего, что видно вызывающему, одним ответом

### Аптечки и участники

- `GET /v1/med-kits` — свои аптечки со счётчиками
- `POST /v1/med-kits` — завести аптечку
- `GET /v1/med-kits/{medKitId}` — аптечка вместе с содержимым
- `DELETE /v1/med-kits/{medKitId}` — удалить, при желании с переносом содержимого
- `POST /v1/med-kits/{medKitId}/invitations` — ключ приглашения с ограниченным сроком
- `POST /v1/med-kit-memberships` — вступить по ключу
- `DELETE /v1/med-kit-memberships/{medKitId}` — выйти

### Упаковки

- `POST /v1/med-kits/{medKitId}/drugs` — завести упаковку в аптечке
- `GET /v1/drugs/{drugId}` — упаковка вместе с бронями на неё
- `PATCH /v1/drugs/{drugId}` — правка описания и исправление количества
- `DELETE /v1/drugs/{drugId}` — выбросить
- `POST /v1/drugs/{drugId}/intakes` — списать съеденное
- `PUT /v1/med-kits/{targetMedKitId}/drugs/{drugId}` — перенести в другую аптечку
- `PUT /v1/drugs/{drugId}/sync/{syncId}` — синхронизация: съеденное и бронь одной транзакцией

### Брони

- `GET /v1/reservations` — свои брони по всем упаковкам
- `POST /v1/reservations` — завести бронь
- `GET /v1/reservations/{drugId}` — своя бронь на упаковку
- `PATCH /v1/reservations/{drugId}` — изменить
- `DELETE /v1/reservations/{drugId}` — отменить

### Справочник и словари

- `GET /v1/drug-templates` — поиск по названию, латинскому названию, веществу и производителю
- `GET /v1/drug-templates/{templateId}` — запись справочника
- `GET /v1/form-types` — формы выпуска
- `GET /v1/quantity-units` — единицы измерения

Список сверяется с контрактом тестом `ReadmeRoutesTest`: разойтись молча он не может.

## API документация

После запуска — Swagger UI и сам документ:

```
http://localhost:8080/swagger
http://localhost:8080/v3/api-docs
```

Актуальный контракт лежит в [open-api.yaml](open-api.yaml) — его можно открыть, не поднимая
приложение. Файл порождаемый и защищён `OpenApiSnapshotTest`: если контракт изменился, а файл нет,
сборка падает. После намеренного изменения API перегенерировать в том же коммите:

```bash
./gradlew test -DupdateOpenApi=true
```

## Схема базы данных

Схему описывают объекты `Table` в `src/main/kotlin/.../db/tables`, а
[db/schema.sql](db/schema.sql) из них **порождается** — это производная, а не второй источник.
Файл применяется при инициализации Postgres в compose, поэтому на чистой машине схема появляется
сама.

Ни миграций, ни `ALTER`: схема создаётся с нуля. После правки таблиц перегенерировать в том же
коммите, за этим следит `SchemaSnapshotTest`:

```bash
./gradlew test -DupdateSchema=true
```

## Ключи подписи JWT

**В Docker делать ничего не нужно.** Сборка образа сама запускает
`src/main/resources/certs/gen.sh`, а он идемпотентен: если пары нет — создаёт, если она уже лежит
в `src/main/resources/certs/` — не трогает. Так что положенные вручную ключи сохраняются, а на
чистом клоне ключ появится сам. Ни переменных, ни параметров.

Для запуска на хосте (`./gradlew bootRun`) тот же скрипт, один раз:

```bash
src/main/resources/certs/gen.sh
```

Ключи в git не попадают (`.gitignore`). Ротация только явно, через `--force`: она инвалидирует все
уже выданные токены.

## Запуск с Docker Compose

### Локальная разработка

Ничего настраивать не нужно: при запуске с профилем `dev` (из IDE или `./gradlew bootRun`) Spring
сам поднимает Postgres из [compose.dev.yaml](compose.dev.yaml) и подставляет параметры
подключения. Схема та же, что в проде.

### Прод-подобная проверка

`application-mock-prod.properties` — это и есть продовая конфигурация: всё, что не секрет, лежит
там и в git. Профиль `prod` ничего не повторяет, он активируется вторым
(`SPRING_PROFILES_ACTIVE=mock-prod,prod`) и доописывает только скрытые значения. Поэтому стенд
проверяет ровно то, что поедет в прод.

```bash
docker compose -f compose.mock-prod.yaml up -d --build
```

Порт снаружи 18080, чтобы стенд не конфликтовал с приложением, запущенным из IDE.

### Прод

Секреты — реальный `registration.secret` и пароль БД — берутся из `application-prod.properties`
(файл вне git) либо из docker secrets, которые перебивают даже его. Пароль Postgres нужен
контейнеру БД, поэтому только файлом:

```bash
mkdir -p secrets
openssl rand -base64 32 > secrets/postgres_password
printf '%s' "ваш-секрет-регистрации" > secrets/registration.secret

docker compose -f compose.yaml up -d --build
docker compose -f compose.yaml logs -f med-app-server
```

Приложение читает `/run/secrets` через `configtree`: имя файла становится именем свойства, поэтому
значение не дублируется и обёртка над entrypoint не нужна.

Наружу смотрит только Caddy: приложение и Postgres портов не публикуют — на этом же держится
доверие к `X-Forwarded-For`.

### Справочник препаратов

Загружается при инициализации Postgres, во всех трёх профилях. Порядок задан именами файлов в
`docker-entrypoint-initdb.d`:

1. `db/schema.sql` → `01-schema.sql` — схема приложения, она создаёт и таблицы справочника;
2. `db/load-catalogue.sh` → `02-load-catalogue.sh` — данные справочника, если дамп есть.

Дамп в git не попадает — это закрытые данные. Монтируется каталог `init-scripts` целиком, а не
файл: при отсутствии файла Docker создал бы на его месте каталог, и инициализация базы упала бы.
Если дампа нет, загрузчик сообщает об этом и пропускает шаг — приложение поднимется, но
`GET /v1/drug-templates` вернёт пустой список.

Выгрузка скраппера в исходном виде для загрузки не годится: она несёт свои `CREATE TABLE` и
спорит со схемой приложения. Преобразовать в data-only можно `db/rewrite-catalogue-dump.py`;
загрузчик проверяет это сам и отказывается грузить необработанный дамп.

## Конфигурация

Три профиля, каждый со своим файлом:

| Профиль | Файл | Роль |
|---|---|---|
| `dev` | `application-dev.properties` | локальная работа, ослабленные сроки и лимиты |
| `mock-prod` | `application-mock-prod.properties` | **вся продовая конфигурация**, лежит в git |
| `prod` | `application-prod.properties` | только скрытые значения, вне git |

Прод запускается как `mock-prod,prod`: второй профиль доописывает первый. Поэтому настройки
поведения правятся в `mock-prod` и автоматически действуют в проде, а стенд проверяет ровно то,
что поедет в прод.

Основные параметры:

```properties
# Срок действия JWT токена (в минутах)
authentication.termInMinutes=10
# Срок действия ключа на присоединение к аптечке (в минутах)
medkit.share.termInMinutes=15
# Секрет для регистрации (отбиваем залётных ботов)
registration.secret=your-secret-here
# База данных
spring.datasource.url=jdbc:postgresql://localhost:5432/medapp-server-db
# Период, в течение которого с одного адреса нельзя зарегистрироваться заново
registration.timeout.InSeconds=30
# Сколько регистраций с адреса до ограничения
registration.timeout.BanNumber=1
```

## Тестирование

```bash
# Весь набор: правила, сценарии, гонки, откаты, число запросов
./gradlew test

# Планы запросов на объёме — отдельным набором, поднимает фикстур на сорок тысяч строк
./gradlew queryPlanTest
```

Тесты идут против настоящего Postgres в Testcontainers, а не H2: поведение зависит от СУБД.

## Безопасность

- JWT, RSA-ключи для подписи, stateless-сессии.
- Валидация входных данных; величины едут строкой и проверяются образцом.
- Запросы параметризованные — их строит Exposed, конкатенации SQL в приложении нет.
- Доступ проверяет сам запрос: чужая строка не читается, а не «читается и отбрасывается».
- Конкурентность держится на версиях: `FOR UPDATE` и пессимистичных блокировок в проде нет.

## Что стережёт репозиторий

| | что проверяется | когда |
|---|---|---|
| тесты | набор целиком и планы запросов на объёме | на каждый PR и push в main |
| CodeQL | статический анализ: инъекции, утечки, небезопасные умолчания | на PR, на push и по понедельникам |
| проверка зависимостей | PR не добавляет зависимость с известной уязвимостью | на каждый PR |
| dependabot | обновления зависимостей и самих actions | раз в неделю |

Чего пока нет: проверки контрольных сумм зависимостей
(`gradle/verification-metadata.xml`). Файл на тысячи строк, который ломается от каждого
обновления — то есть от каждого PR dependabot; браться за него имеет смысл, когда станет видно,
сколько таких PR в неделю.

## Логирование

Логи выводятся только в консоль в соответствии с Privacy by Design:

- `DEBUG` для пакета приложения, `INFO` для Spring;
- на диск не сохраняются;
- не содержат идентификаторов, количеств и прочего, что раскрывало бы чужие данные.
